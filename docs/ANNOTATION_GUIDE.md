# EmoLabel 어노테이션 가이드 v0.2

2026-09-14 · 산학2 공유용 · 후속 수집에 적용할 운영안

## 1. 무엇에 라벨을 붙이나

**선택한 발화에서 화자가 드러내는 주된 감정**에 라벨을 붙입니다. 장면의 슬픈 사연, 배경음악, 시청자가 느끼는 감정, 배우의 실제 속마음이 대상은 아닙니다.

한 샘플은 **한 화자의 의미가 이어지는 발화 단위**입니다. 반드시 문법상 한 문장일 필요는 없습니다. 같은 화자가 같은 감정으로 이어 말한 짧은 두 문장은 함께 사용할 수 있습니다. 화자나 주된 감정이 바뀌면 자연스러운 경계에서 나눕니다.

이번 공유본은 neutral 26, angry 25, sad 25, happy 25의 **101개 파일럿**입니다. 당초 25개씩 100개 목표에서 neutral 1개를 추가 보존했습니다. 이후 배치 목표는 별도로 배정합니다.

## 2. 좋은 구간 고르기

- 말하는 사람의 얼굴과 음성이 확인되어야 합니다. 그 화자의 얼굴만 보이는 구간이 가장 좋습니다. 자동 얼굴·화자 수는 참고값이지 보증이 아닙니다.
- 알아들을 수 있는 의미 있는 발화를 고릅니다. 보통 3–12초가 작업하기 편하지만, 길이를 맞추려고 다른 화자의 말이나 다른 감정을 끼워 넣지 않습니다.
- 말의 시작과 끝을 자르지 않습니다. 필요한 만큼 짧은 여유를 두되, 긴 무음이나 다른 사람의 발화는 포함하지 않습니다.
- 한 원본 숏츠에서 최대 3개를 우선 기준으로 합니다. 같은 장면을 재편집한 영상도 중복 후보로 확인합니다. 작품·배우·채널을 분산합니다.
- BGM이나 환경 소음이 있어도 목소리의 말투와 감정이 충분히 들리면 사용할 수 있습니다. 노래의 보컬이나 타인의 말이 겹치면 더 엄격하게 검토합니다.
- 음성이 가려지거나, 화면과 말하는 사람이 불일치하거나, 네 감정 중 하나로 안정적으로 정하기 어려우면 보류합니다. 양을 채우려고 억지로 넣지 않습니다.

위 길이·수량 기준은 이번 연구의 운영 기준이며 보편적인 정답은 아닙니다. 기존 101개에는 2초 미만 6개와 최대 약 16.82초 구간도 있어, 향후 재검수 항목으로 남깁니다. 이번 공유 과정에서 임의로 제외하거나 재절단하지 않았습니다.

## 3. 네 가지 감정

| 라벨 | 판단 기준 | 혼동하지 않을 것 |
|---|---|---|
| neutral | 뚜렷한 기쁨·분노·슬픔 없이 담담하게 설명·질문·응답 | 모르겠거나 애매한 상태가 아님 |
| angry | 짜증, 항의, 비난, 적대감, 분노가 말투에 드러남 | 큰 소리만으로 결정하지 않음 |
| sad | 서러움, 상실감, 낙담, 슬픔이 발화에 드러남 | 슬픈 사연이나 눈물만으로 결정하지 않음 |
| happy | 즐거움, 기쁨, 만족감 등이 말투에 드러남 | 예의상 웃음·비웃음·안도라는 상황만으로 결정하지 않음 |

예: “엄마가 형만 좋아해서 화나면서 서럽다”는 상황 설명만으로 angry/sad를 고르지 않습니다. 선택 구간에서 따지고 몰아붙이는 표현이 우세하면 angry, 목이 메거나 풀이 죽고 서러움을 드러내는 표현이 우세하면 sad를 고려합니다. 울면서 화를 내면 angry일 수도 있고, 눈물 없이도 sad일 수 있습니다.

1차 판단은 목소리를 듣고, 얼굴을 함께 확인합니다. 음성은 담담한데 장면·표정만 슬픈 경우에는 그 차이를 메모하고 재검토합니다. 기존 정답은 영상도 참고했지만 현재 비교 모델은 음성만 입력받았다는 점을 유지합니다. 평가 기준 자체를 바꿀 때는 새 버전으로 관리합니다.

## 4. 애매함과 품질 메모

세 번 정도 확인해도 두 라벨이 비슷하면 보류합니다. neutral로 처리하지 않습니다. 주 감정이 분명하면서 다른 감정도 보이면 주 라벨과 SECONDARY를 기록할 수 있습니다. 모델의 confidence는 아래 CONF와 다릅니다.

| 항목 | 기록법 |
|---|---|
| CONF | 3: 명확 / 2: 우세한 감정은 있으나 재검토 필요 / 1: 결정 어려움 |
| QUALITY | A: 얼굴·음성·경계가 명료 / B: BGM·다른 얼굴 등 있으나 판단 가능 / C: 핵심 단서가 가려져 보류 |
| AMBIG | 0: 주 감정을 구분 가능 / 1: 혼합·모호해서 단일 라벨이 불안정 |
| SECONDARY | 부차 감정이 있을 때만 neutral, angry, sad, happy 중 기록. 없으면 공란 |
| FLAGS | 아래 조건을 쉼표로 연결. 없으면 공란 |

FLAGS: `BGM` 배경음악, `BGM_VOCAL` 노래 보컬, `NOISE` 환경 소음, `OTHER_FACE` 다른 얼굴, `OVERLAP` 다른 화자의 말 겹침, `MIXED` 혼합 감정, `CONTEXT` 문맥 의존, `UNCLEAR_TEXT` 대사 불명확.

```text
CONF=3; QUALITY=A; AMBIG=0; SECONDARY=; FLAGS=
CONF=2; QUALITY=B; AMBIG=0; SECONDARY=sad; FLAGS=BGM,MIXED
CONF=1; QUALITY=C; AMBIG=1; SECONDARY=angry; FLAGS=OVERLAP,MIXED
```

현재 UI는 첫 번째 예시를 자동으로 채웁니다. **자동 기본값을 검수 완료로 간주하지 말고 매번 직접 확인하세요.** C 또는 AMBIG=1도 앱에서는 저장될 수 있지만 clean 평가 세트와는 분리합니다. CONF=2는 독립 재검수 후 채택 여부를 결정합니다.

이번 101개 중 34개는 CONF·QUALITY·AMBIG가 기록되지 않았습니다. 미기록을 자동으로 CONF=3/A/0으로 보충하지 않았습니다. 나머지에 기록된 값도 복수 라벨러 검증을 뜻하지 않습니다.

## 5. 한 샘플 작업 순서

1. 원본을 보고 후보 구간을 선택합니다. 얼굴·화자·발화 경계를 확인합니다.
2. 구간을 재생하고 **감정 모델/GPT의 라벨을 보기 전에** 사람 판단을 기록합니다.
3. 실제 들리는 대사로 ASR을 수정합니다. 사투리·비문·반복·말더듬을 의미상 자연스럽게 고치지 않습니다. 안 들리는 단어는 추측하지 않고 재청취하거나 `UNCLEAR_TEXT`로 보류합니다.
4. 감정, 품질 메모, 본인 annotator ID를 입력합니다. 배우를 확실히 알 때만 이름을 쓰고, 성별 등 부가 속성을 모르겠으면 unknown으로 둡니다.
5. 저장 후 `data/output/{clip_id}/annotation.json`이 실제로 있는지 확인합니다. 추출만 한 폴더는 라벨링 완료가 아닙니다.
6. 담당량이 끝나면 진행상황 도구로 개수와 누락 파일을 확인하고, 본인의 output 폴더만 제출합니다.

지금 단계에서 valence/arousal은 평가하지 않습니다. 기존 앱이 저장한 기본값 4 또는 파일의 null/미기록을 실제 평정으로 분석하지 않습니다. 원본 필드의 값은 그대로 보존합니다.

## 6. 연구실 공동 작업

- 시작 전 동일한 8–12개를 두 사람이 서로의 답을 보지 않고 라벨링해 기준을 맞춥니다. 불일치를 토의한 뒤 가이드 변경을 기록합니다.
- 각자 고유 ID와 별도 작업 폴더를 사용합니다. 공용 PC에서는 한 번에 한 명씩 작업하고, 사용자 교대 때 화면에 남은 ID를 반드시 바꿉니다.
- 중복 수집을 줄이도록 담당 원본 URL과 목표 라벨을 먼저 배정합니다. 목표 라벨과 실제 발화가 다르면 실제 감정을 우선합니다.
- 수집자는 본인 배치, 검수자는 다른 사람 배치를 확인하는 식으로 역할을 나눕니다. 이의가 있으면 원본 라벨은 남기고 별도의 재검수 기록과 사유를 작성합니다.
- 현재 체감 속도는 후보 탐색 포함 약 10개/인·시간입니다. 100개 신규 수집에는 약 10인·시간에 설치·재검수 시간이 추가되는 계획값이며 보장 속도는 아닙니다.
- 모델 예측과의 불일치는 재청취 후보일 뿐 자동 오답 판정이 아닙니다. 모델을 보고 라벨을 변경했다면 기존 평가와 섞지 않고 버전을 새로 만듭니다.

## 7. 제출 체크

- [ ] clip.mp4 + audio_16k.wav + annotation.json이 같은 clip_id 폴더에 있음
- [ ] 사람 확정 대사는 `labels.transcript`, 사람 감정은 `labels.emotion`에 있음
- [ ] `prelabels.asr.text` 등 기계 초안과 최종값을 혼동하지 않음
- [ ] URL·구간·annotator ID·품질 메모를 확인함
- [ ] 모델/GPT 제안을 최종 사람 라벨에 자동 덮어쓰지 않음
- [ ] `.env`, 토큰, 쿠키, 모델 가중치, 원본 전체 다운로드 폴더를 제출 ZIP에서 제외함

이 가이드는 파일럿의 모든 샘플이 고품질임을 인증하는 문서가 아닙니다. 미기록 품질 항목과 단일 라벨러 한계는 비교 보고서와 함께 공개합니다.
